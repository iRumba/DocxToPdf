# Стратегия тестирования

## Уровни тестирования

### Юнит-тесты

- **Фреймворк:** {{unit_test_framework}}
- **Покрытие:** Все публичные методы сервисов и контроллеров
- **Моки:** {{mocking_library}}
- **Запуск:** `{{unit_test_command}}`

### Интеграционные тесты

- **Фреймворк:** {{integration_test_framework}}
- **Покрытие:** Взаимодействие с БД, внешними сервисами
- **Запуск:** Требуется запущенная БД (через Docker Compose)
- **Команда:** `{{integration_test_command}}`

### E2E тесты (если применимо)

- **Инструмент:** {{e2e_tool}}
- **Запуск:** `{{e2e_command}}`

## Запуск тестов

### Все тесты

```bash
{{all_tests_command}}
```

### Только юнит-тесты

```bash
{{unit_tests_only_command}}
```

### Только интеграционные

```bash
{{integration_tests_only_command}}
```

## CI/CD

Тесты запускаются автоматически при каждом Pull Request:
- {{ci_platform}} — конфигурация в `{{ci_config_path}}`
- Требования к прохождению: все тесты зелёные, покрытие не ниже {{coverage_threshold}}%

## Структура тестов

```
tests/
├── Unit/
│   ├── Services/
│   └── Controllers/
├── Integration/
│   ├── Database/
│   └── Api/
└── E2E/
```

## Написание тестов

- Тесты пишутся на том же языке, что и основной код
- Именование: `{ClassName}Tests.cs` / `{ClassName}Test.php` / `test_{module}.py`
- Один тестовый класс — один тестируемый класс
- Один тестовый метод — один сценарий
