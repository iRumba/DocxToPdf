# Стратегия ветвления (Git Flow)

Git Flow — модель ветвления с двумя основными и тремя вспомогательными типами веток.

## Основные ветки

- **main** — продакшн-релизы. Всегда стабильна.
- **develop** — основная ветка разработки. Интеграционная.

## Вспомогательные ветки

- **feature/<название>** — от `develop`, новая функциональность. После завершения → PR в `develop`, ветка удаляется.
- **release/<версия>** — от `develop`, подготовка релиза. После завершения → PR в `main` и `develop`, ветка удаляется.
- **hotfix/<название>** — от `main`, срочные исправления продакшна. После завершения → PR в `main` и `develop`, ветка удаляется.

## Процесс

1. Новая задача → создаётся Issue
2. От `develop` → `feature/название`
3. Разработка в ветке
4. Pull Request в `develop`
5. Code Review
6. Слияние с удалением ветки
7. Релизный цикл → `release/*` → PR в `main`
