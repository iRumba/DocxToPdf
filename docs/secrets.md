# Секреты проекта

> ⚠️ **Важно:** Этот файл содержит ТОЛЬКО информацию о существовании секретов.
> Реальные значения секретов никогда не хранятся в репозитории и не указываются в этом файле.
> Секреты принадлежат среде (окружению) и управляются через менеджеры секретов / переменные окружения.

## Золотое правило

**Секреты НИКОГДА не хранятся в явном виде.** Нигде:
- ❌ В репозитории (код, конфиги, документация)
- ❌ В файлах на диске (`.env`, `secrets.json`, `credentials.ini`)
- ❌ В общих папках, шаблонах, docker-compose файлах

## Секреты по средам

| Переменная | Описание | Модуль/Инструмент | Среда | Где взять |
|------------|----------|------------------|-------|-----------|
| `{{secret_var_1}}` | {{secret_description_1}} | {{secret_module_1}} | {{secret_env_1}} | {{secret_source_1}} |
| `{{secret_var_2}}` | {{secret_description_2}} | {{secret_module_2}} | {{secret_env_2}} | {{secret_source_2}} |

**Поля:**
- `Переменная` — имя переменной окружения
- `Описание` — что это за секрет
- `Модуль/Инструмент` — для какого модуля или инструмента нужен
- `Среда` — где используется (dev, staging, prod)
- `Где взять` — ссылка на менеджер секретов, админскую панель, инфраструктурную команду

## Файлы, исключённые из репозитория

Эти файлы **должны** быть в `.gitignore` проекта:

- `.env`
- `.env.local`
- `*.env.local`
- `secrets/`
- `docker-compose.override.yml` (если содержит секреты)
- `appsettings.Local.json` (для .NET)
- `credentials.*`
- `*.key`
- `*.pem`
- `*-secret.*`

## Пример `.env.example`

Файл `.env.example` **можно** хранить в репозитории, но исключительно с плейсхолдерами:

```env
# База данных
DB_HOST=localhost
DB_PORT=5432
DB_USER=your_user
DB_PASSWORD=your_password_here
DB_NAME={{db_name}}

# Kafka
KAFKA_BOOTSTRAP_SERVERS=localhost:9092
KAFKA_API_KEY=your_api_key_here
KAFKA_API_SECRET=your_api_secret_here
```

## Где и как настроены секреты

| Среда | Способ хранения | Кто настраивает |
|-------|----------------|-----------------|
| **Локальная разработка** | `.env` (создать из `.env.example`) | Разработчик |
| **CI/CD** | Переменные окружения {{ci_cd_platform}} (Secrets) | DevOps / Team Lead |
| **Staging** | {{staging_secret_manager}} | DevOps |
| **Production** | {{production_secret_manager}} | DevOps / Admin |

## Работа с секретами через `secrets-manager`

Если в сессии opencode доступен встроенный агент **`secrets-manager`**, все операции с секретами выполняются через него:

- Получение значения секрета
- Регистрация нового секрета
- Проверка существования секрета
- Добавление переменной окружения в реестр секретов

Используй: `task(subagent_type="secrets-manager", prompt="...")`

## Важно: что не относится к секретам проекта

Файл `secrets.md` содержит **только секреты, необходимые для работы приложения** (пароли БД, API-ключи интеграций).

**Не включайте сюда:**
- Токены доступа к Git-платформе (GITVERSE_TOKEN, GITHUB_TOKEN и т.д.) — это инфраструктура команды
- Переменные CI/CD — это настройки среды сборки
- Персональные ключи разработчиков

Эти данные относятся к мета-информации и хранятся в DevelopmentTeam-метаданных, а не в проекте.
